- [ ] 在隔离 Windows 环境运行当前构建，验证本机 CA 的生成、安装及 IDE 的实际信任。

- [ ] 整理实际域名和路由，不把当前默认两个域名当作新版 IDE 的完整范围。

## P1：云端原生网关与号池

- [ ] 固定 Hub 的经验证源码版本与许可证，建立可维护的账号 / 协议适配接口。

- [ ] 账号健康、区域、模型权限、余额、并发、冷却和会话亲和。
- [ ] 使用平台设备凭证的客户端 HTTPS 通道，原生路由白名单和请求 ID。

- [ ] 确认不会把上游凭据发到客户设备；无未授权任意 URL 转发。
- [ ] 单账号池所有者与可恢复租约，明确已派发请求的重试边界。
- [ ] 两个客户、不同会话的原生链路隔离测试。

退出条件：真实客户通过本地代理使用云端账号，客户本机没有上游 Token，并保留原生 IDE 的受支持行为。

## P2：客户授权、激活码与额度账本

- [ ] PostgreSQL 模型与版本化迁移：客户、设备、套餐、激活码、权益、请求、用量回执、账本、审计。
- [ ] 设备挑战、密钥绑定、会话续期与吊销；防止旧签名重放换取新会话。
- [ ] 激活码安全生成、摘要存储、原子兑换、重复兑换幂等、设备数量约束。
- [ ] 固定额度与有效期、多卡先到期先消费、并发准入和模型权限。
- [ ] 原子预算预留、幂等结算、失败释放、到期、补偿及不可变账本。
- [ ] 缺失用量待核对、崩溃恢复、可靠回执写入；不能靠 Redis 或 JSONL 保证钱账。
- [ ] 低余额长响应的尾部成本控制、未知单次成本边界与平台承担政策。
- [ ] 数据库故障停止新计费准入；冻结 / 耗尽 / 到期拒绝新的请求。
- [ ] 并发兑换、请求重放、跨设备、超额与恢复的数据库集成测试。

退出条件：同一码不重复发放权益，每笔请求不重复结算，客户余额不为负，所有异常有可核对记录。
